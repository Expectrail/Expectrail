Quickstart / a no-credentials first pass

Get a result you can explain.

Start in a checkout of Expectrail on Linux with Python 3.12+, a virtual display, software OpenGL, patch, curl and unzip. Godot 4.7.2 is fetched and SHA-512 checked on first use unless you already configured a binary. Installation evidence and platform limits.

Use a fresh Bash shell and run these six blocks in order, in the same shell. This walkthrough deliberately removes the vision key and cap from that shell. Nothing is sent to a vision model; passing engine checks need review. No-settings behavior.

Nonzero exits below are expected results, not instructions to bypass a check. Do not chain the six steps with && or run the whole walkthrough with set -e. A missing tool is a separate problem to fix before continuing.

1 Install2 Doctor3 Sample4 Project5 Verify6 Report

1. Install in a virtual environment

python3 -m venv .venv &&
. .venv/bin/activate &&
python3 -m pip install . &&
expectrail --version

Expected exit: 0. This installs the checkout, not a package from PyPI. Installed-command row.

2. Check this machine

unset MODEL_API_KEY EXPECTRAIL_SAM_USD_CAP
expectrail doctor --json > doctor.json

Expected exit: 3, with exactly vision-key and vision-cap missing when the machine’s other prerequisites are ready. Read doctor.json; fix any other missing requirement first. Doctor checks prerequisites, not a change, and never prints the key. Doctor evidence and limits.

3. Run the bundled sample

expectrail sample --jobs-root runs/quickstart-sample --json > sample.json

Expected exit: 3. The three jobs must complete as needs-review, reject, needs-review: clean, seeded fall-through bug, repair. The sample’s success condition is accept/reject/accept, so this deliberately incomplete first pass does not meet it. The game still replays and the engine checks run. Sample scope · Vision requirement.

This is not the same as the site’s Run it recordings. This command has no recorded-vision substitute. Run it is a separate path.

4. Point at a project

PROJECT=tests/projects/crate-run

Expected exit: 0. Use the small included project first. After this walkthrough, replace the value of PROJECT with your checkout path and adapt the relative paths in step 5. The measured scope is the bundled game and the cited second-project integration, not arbitrary projects. Project-by-path evidence.

PROJECT/
  project/project.godot
  routes/walk.json
  specs/crate-stays-above-floor.json  # an unapproved draft

Your routes must use your game’s inputs and its harness-compatible scene bindings. Checks must describe your intended behavior. A person must review and approve them; this walkthrough never adds or copies an approval. Harness limits · Drafts and approval.

5. Ask for verification

expectrail verify --head "$PROJECT" --game project \
  --routes 'routes/*.json' --specs specs \
  --jobs-root runs/quickstart-project --json > verification.json

Expected exit for this example: 2, needs-review. Its only check is a draft: no approved check ran, so there is no judged replay of this project. This is a test of the project-path and approval boundary, not a demonstrated pass or evidence that your game was exercised. Verification-job scope · Second-project limits.

For a real change, supply a trusted base checkout with --base; the job reads checks and routes from that base. Keep job output outside the game and checks folders. Input and job boundaries.

6. Read the job’s result

JOB=$(python3 -c 'import json; print(json.load(open("verification.json"))["id"])') &&
expectrail report "$JOB" --jobs-root runs/quickstart-project

Expected exit: 2 again. The report names the decision, reasons and evidence location. It does not turn a draft or a missing observer into an accept. Report and decision evidence.

Before expecting an accept

A verification needs both MODEL_API_KEY and a finite, nonnegative EXPECTRAIL_SAM_USD_CAP in the verifier’s environment, plus usable vision answers and approved checks. Setting them alone does not establish any behavior. Reaching the cap can leave a question unanswered. Current observer rule · Vision scope and cost limits.

The recorded example cost is up to $0.60 for both prompts over one 120-frame run; other runs can differ. This is a historical figure, not a suggested cap or a guarantee. Recorded cost source · Observer evidence.

CI is configured to extract and execute these six command blocks, including installation, then check the saved jobs rather than treating an exit alone as success. No credentials, approvals or paid calls are added. Command and quickstart test evidence.
