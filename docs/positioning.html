What an agent-run test result establishes

A passing test establishes the assertions that were exercised. Python’s test-framework documentation defines a test case in terms of particular inputs and expected responses. If an agent only runs logic assertions, the successful exit does not by itself show that the player was drawn visibly or above the floor. This is an inference about that limited test setup, not a claim that agents cannot run visual tests. Python unittest documentation (reviewed November 14, 2026) · Expectrail’s measured visual-check scope.

Expectrail adds an explicit policy to that setup: routes and approved checks from a supplied base, declared windows and tolerances, and a combined engine/vision result. An engine pass without usable vision remains needs-review in the installed path. The ledger’s vision results are on seeded defects in one game; they are not a general catch rate. Policy and observer evidence · Vision measurements (ledger reviewed November 14, 2026).

An agent can invoke a verifier or build assertions that cover the same behavior. The distinction is the checks and evidence actually required for the decision, not whether an agent pressed the run button. This is our interpretation of the test-framework semantics and Expectrail’s recorded rule, not an exclusive feature claim. Test-framework semantics · Expectrail’s rule (reviewed November 14, 2026).

Public documentation: Ziva and nunu.ai

Both products describe observing a running game or app and checking outcomes. We have not installed or benchmarked either product. The following is a desk review of the linked first-party pages, accessed November 14, 2026; product documentation is a statement from its publisher, not a result measured by Expectrail.

Ziva

Ziva’s Create and test guide describes keyboard/mouse input, screenshots and error inspection. It documents a full playtest agent with pass, fail or blocked outcomes and optional video recording. Its Full game tester page describes reading code, pausing between actions, pursuing user-supplied goals and using hosted models. That page also says playtesting may temporarily change project files for diagnostics, while its comparison table says the playtest agent ships without write tools. This desk review does not resolve that distinction. Sources accessed November 14, 2026; the Create and test page states it was updated that day.

nunu.ai

The agent introduction describes a screenshot/action loop with optional game state and SDK functions. Verification Tests documents ordered steps, explicit expected results, a time budget and per-check outcomes including skipped or blocked. Its Minion guide documents self-hosted Windows PCs and connected Android devices, with access enabled on request. We therefore make no claim that nunu.ai lacks explicit checks, evidence review or self-hosting. Sources accessed November 14, 2026; Verification Tests states an October 1, 2026 update.

Expectrail’s limits belong in the comparison

The two-job Action merged in #429: candidate capture is separate from base-side judging with recorded vision. Its cited tests use stand-ins; this review adds no hosted acceptance demonstration. The bundled recording can lack answers for novel frames and combat, and clearance is advisory on Expectrail’s own repository. The earlier composite actions remain engine-only. The installed verifier’s current vision default has offline test evidence, while its cited live orchestrator run predates that default. No ledger row has isolated or protected grade. Action limits · Current verifier evidence (reviewed November 14, 2026).

The game originates its captured frames and trace, and the replay sandbox shares the host kernel. Expectrail therefore does not establish immunity to a malicious game forging its own evidence. Coverage is limited to the supplied checks and exercised routes. Capture boundary · Sandbox boundary · Coverage scope (reviewed November 14, 2026).

Use this review to decide what to evaluate: an existing regression with an observable requirement, a repeatable route and evidence you can inspect. Keep unit tests, exploratory playtesting and human judgment alongside it. This is a recommended evaluation approach, not a claim of superiority.
