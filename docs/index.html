How it works · what’s new

Models look. Plain code decides.

Coding agents can make unit tests pass while the software is broken: a character inside the floor, a hidden checkout button, a missing texture, a feature switched off to quiet a check.

Expectrail checks configured Godot routes using two sources: what the engine recorded and usable live or exact recorded visual answers. Plain code, never a model, gives the verdict.

Plain-code evaluator

Ordinary code judges each approved check from the engine’s record and what vision saw. No model decides. Acceptance needs both observations for every required check; missing vision needs review unless a check already fails.

Evidence ledger

Each capability with its test, record or run, and its limits. Open

Run it says whether it can start a run right now and serves clearly labelled earlier evidence when it cannot. The ledger links the recorded visitor runs through the deployed service. Status

What this does not establish

  • Routes and approved windows cover only what they exercise. Check scope
  • The game writes its own frames and trace, so a malicious game could fake them. Capture limits
  • No ledger row has isolated or protected grade; a verdict is not release clearance. Sandbox · Signing
  • An accept needs engine and visual evidence. Without vision settings, passing engine checks need review; the current default is tested offline. Vision default
  • Saved demo captures are for looking; viewing them verifies nothing. Demo scope
