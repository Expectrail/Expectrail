How it works · what’s new

Models look. Plain code decides.

Coding agents can make unit tests pass while the software is broken: a character inside the floor, a hidden checkout button, a missing texture, a feature switched off to quiet a check.

Expectrail replays the change and cross-examines two sources: what the engine recorded and what vision saw on screen. Plain code, never a model, gives the verdict.

Plain-code evaluator

Ordinary code judges each approved check from the engine’s record and what vision saw. No model decides. It accepts only when both agree; missing vision means needs-review.

What this does not establish

  • Routes and approved windows cover only what they exercise. Check scope
  • The game writes its own frames and trace, so a malicious game could fake them. Capture limits
  • No ledger row has isolated or protected grade; a verdict is not release clearance. Sandbox · Signing
  • Without vision settings, passing engine checks need review; the current default is tested offline. Vision default
  • Saved demo captures are for looking; viewing them verifies nothing. Demo scope
