# Deploy the Expectrail hub

Sean owns these steps. The hub has its own script, `expectrail-hub`, its own SQLite Durable Object namespace and the custom domain `hub.expectrail.tech`. Sign-in lists repositories visible through the user's GitHub App installation. Seeing a repository here does not establish that its CI has produced a verified run.

1. Check out a reviewed revision containing both the Worker and the #786 store. From the repository root, run `cd apps/hub-edge`, then `node --test`. Check that `hub-store.js` exports the class factory used by `worker.js`. Copy `wrangler.toml.example` to the ignored local `wrangler.toml`. Remove the entire `routes` line from this local copy for the first deploy. Keep `workers_dev = false`, `preview_urls = false`, the HUB binding and the SQLite migration. Confirm that the script name is exactly `expectrail-hub`.
2. Run `node prepare-assets.mjs` from that directory. It requires a fresh `.public` directory. For a repeat build, move the previous generated directory aside first. Check that the output contains three stylesheets, two fonts and the headers file. Run `wrangler deploy --dry-run` with the local configuration. Resolve any missing module, asset or binding before continuing.
3. Sign into Wrangler for the Cloudflare account that owns the expectrail.tech zone. Check the account with `wrangler whoami`. Run `wrangler deploy` with the route still absent to create the unconfigured Worker and its namespace. In Workers & Pages → expectrail-hub → Settings → Domains & Routes, confirm the Worker has no public hostname.
4. In the owning GitHub organization's Settings → Developer settings → GitHub Apps, open the hub App or choose New GitHub App. Set the homepage to `https://hub.expectrail.tech`, callback to `https://hub.expectrail.tech/callback`, setup URL to `https://hub.expectrail.tech/installed` and webhook URL to `https://hub.expectrail.tech/github/events`. Enable the webhook. For this sign-in slice use repository Metadata read-only, leave optional permissions off and use selected repositories for the trial. Installation and installation-repository deliveries drive revocation. Publish the operator's privacy statement before inviting outside developers.
5. Generate the App client secret. Generate a separate random webhook secret in a password manager and enter it in GitHub. Generate an independent random cookie signing key with at least 32 bytes of entropy. Set the following on the hub script with `wrangler secret put NAME` from the hub directory, entering each value at the prompt. Use EXPECTRAIL_HUB_CLIENT_ID, EXPECTRAIL_HUB_CLIENT_SECRET, EXPECTRAIL_HUB_WEBHOOK_SECRET and EXPECTRAIL_HUB_COOKIE_KEY. The webhook value must match GitHub's. The cookie key signs one-hour sessions and ten-minute sign-in states. Keep values out of files, screenshots and shell arguments. This flow does not consume an App private key.
6. Under the local config's existing `[vars]` table add `EXPECTRAIL_HUB_APP_SLUG` with the actual public slug from the App URL. Keep `EXPECTRAIL_HUB_ORIGIN` set to `https://hub.expectrail.tech`. Restore the example's single custom-domain line at the top level. Verify that this hostname is free in Cloudflare DNS and Domains & Routes and belongs to this zone. Deploy with `wrangler deploy`. Cloudflare provisions the custom domain's DNS and certificate. Confirm the hostname maps to expectrail-hub and leave the separate API hostname with its existing Worker.
7. Open the hub in a private window, sign in, install the App on one selected trial repository and use Refresh from GitHub. Check that only repositories accessible to that signed-in user through the installation appear. Remove the repository or uninstall, verify a successful GitHub webhook delivery, then reload Projects. Sign out and revisit Projects. Record observed statuses and repository visibility without copying cookies, codes or delivery signatures.

If setup is incomplete, the home page labels sign-in unconfigured. If a callback fails, check the exact callback URL and App credentials. If removals fail, inspect the webhook delivery status and matching webhook secret. To take the hub offline, remove only its custom domain in Domains & Routes and remove the route from your local configuration before another deploy. Preserve its Durable Object state for diagnosis.
