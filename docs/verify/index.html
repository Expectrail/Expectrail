Verify a receipt

A receipt is a signed statement of what Expectrail checked, on which build, under which policy, and what it decided. Check one here against the keys you already trust.

This page applies the same rules as python -m expectrail.receipt trust-check, in your browser. Nothing you choose is uploaded. Clearance is given only when everything is shown: a key from your trust store, a valid signature, the repository, head, build and policy you expect, a validity of at most 7 days that includes now, and every required check passed and exercised on full evidence. Anything this page cannot reproduce exactly, it reports as "cannot tell" rather than guess.

Expectrail has not published an issuer key yet: signing in CI waits on #255, so Run it's receipts are not signed yet. Until then, the two samples below are signed by a throwaway test key, to show the check working.

Your receipt

The keys you already trust. A key carried inside the receipt is never trusted on its own, and a trust store that came with the receipt from the same place proves little. In a v2 store a retired key is trusted only for receipts issued before it retired, and a revoked key for none (where to get Expectrail's store, and how keys rotate).

A field left empty is "not checked", and a receipt with something not checked gets no clearance.

This page reads the receipt with its own strict parser and rebuilds the signed bytes as Python does. A form it cannot reproduce exactly (a timestamp outside RFC 3339, a browser without Ed25519) is "cannot tell": check that receipt with trust-check.
