# 2026-11-14 Receipt v1 first slice

## What changed

Added the `expectrail.receipt/v1` contract: schema, worked example, and writer/reader in one change.

- Schema: `contracts/receipt.v1.schema.json` (canonical JSON, duplicate keys and non-finite numbers rejected via the existing v1 helpers).
- Example: `contracts/examples/receipt.v1.json`.
- Writer and reader: `expectrail/receipt.py`. The writer validates, signs the canonical body (signature field omitted) with Ed25519, and returns the signed document. The reader loads and schema-validates. Private keys are never written.
- Offline trust store: a JSON file of issuer public keys (`expectrail.trust-store/v1`). A key found only inside the receipt is never trusted.
- `python -m expectrail.receipt trust-check RECEIPT --trust-store FILE [--repo OWNER/NAME] [--expect-head SHA] [--expect-policy DIGEST]`: verifies signature and issuer, identity, policy, freshness and completeness, and prints what the receipt does and does not establish. A valid signature on insufficient evidence reports “no clearance”.
- Tests in `tests/test_receipt.py` cover the rejection cases named in the issue (altered evidence, substituted head or build, unknown issuer, stale receipt, removed required check, another repository, self-signed with an embedded key) plus a round-trip and the CLI. Keys are generated in the test; no real key is in any file.

`expectrail/contracts.py` was left unchanged so the discovery freeze continues to hold.
