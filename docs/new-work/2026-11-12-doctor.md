# `expectrail doctor`, and a command line that cannot be read exits 5 (#333)

## What changed
- **`expectrail doctor [--json] [--isolated] [--no-fetch]`** (`expectrail/doctor.py`). One list of what
  a verification needs on this machine, each piece checked the way a run uses it: Python 3.12 or
  later; Godot, found as a replay finds it (fetched on first use) and asked its version (4.7.2); a
  virtual display (`xvfb-run`); OpenGL, by having the engine draw one frame of an empty project,
  started as a replay starts it; free disk; the replay sandbox (bubblewrap, required only with
  `--isolated`); `patch`; `curl` and `unzip`; and whether a vision key is in the environment (present
  or absent; only "is it empty" is looked at, and no value is printed). Every piece that is missing
  names the fix. Exit 0 when nothing required is missing, 3 when something is. It is not a verdict.
- It says what a run without a vision key gives, in two sentences that are both true today: `verify`
  and `sample` judge on the engine's record only and use no key; under the two-observer rule (#327)
  a run without a key still rejects a failing change and accepts nothing.
- **One list, shared with the engine's preflight.** `GodotGate._tools` now asks
  `expectrail.doctor.for_run()` (Godot, the display, OpenGL, disk), the same functions `doctor` runs.
  When `doctor` passes, the preflight's tool check passes; when a job is stopped, its `TOOL_MISSING`
  diagnostic carries the same words and the fix. This makes the preflight stricter than it was: it
  looked only for the engine's file and `xvfb-run`; it now also asks the engine its version, has it
  draw a frame, and looks at free disk. An engine named by `EXPECTRAIL_GODOT` that is not 4.7.2 now
  stops a job; before, it ran.
- **The record**: `expectrail.doctor/v1`, with its schema, example, writer (`doctor.document`) and
  reader (`doctor.problems`, which recomputes `ok` from the rows) in this change.
- **A usage error exits 5.** `expectrail verify` with a missing or unknown option exited 2, which is
  also needs-review. The orchestrator's parser now raises instead of exiting, and the command returns
  5 with the usage and "Nothing was run" on stderr. The same for `status`, `cancel`, `report` and
  `sample`, and for `python3 -m expectrail.orchestrator`. `--help` is still exit 0.
- **CI**: the `test` job installs `requirements-build.txt` and sets `EXPECTRAIL_PACKAGE_TESTS=required`,
  so the package tests run in that required check. The `package` job runs the installed `doctor`
  (it must pass), then with the engine taken away (exit 3, with the fix), then a usage error (exit 5).
- The wheel carries `expectrail.doctor` and the schema.

## What was run
- `python3 -m unittest tests.test_doctor`: 26 tests, OK, 1 skipped (the real-engine test). The engine
  in these tests is a stand-in script and the PATH is a stand-in for `shutil.which`.
- The same with `EXPECTRAIL_ENGINE_TESTS=required` and real Godot 4.7.2 on the builder's machine: 26
  tests, OK. The real engine drew a frame with "Mesa - llvmpipe (LLVM 20.1.2, 256 bits)".
- `python3 -m unittest tests.test_package`: OK with the wheel built (setuptools 84.0.0 on this
  machine, not the pinned 80.9.0), with the three new tests on the installed copy.
- By hand, the wheel installed in a clean venv, run outside the checkout with an empty home and a PATH
  of the venv, `/usr/bin` and `/bin` (this session's machine, not a clean container):
  - `expectrail doctor`: fetched the engine into the empty home, every required piece ok, exit 0, 5.6 s.
    bubblewrap is not installed there: reported as missing and not required.
  - With `xvfb-run` hidden from the PATH: exit 3, "MISSING a virtual display", "fix: sudo apt-get
    install xvfb", and OpenGL "not tried".
  - With `patch` hidden: exit 3, "fix: sudo apt-get install patch".
  - With no way to reach github.com (the proxy settings removed): exit 3, "Godot could not be found or
    downloaded (CalledProcessError)", after the fetch script's five attempts (20 s).
  - `expectrail sample` from that installed copy, through the new preflight: see the pull request for
    its result.
- The full suite: see the pull request.

## Not done
- A release workflow that builds the wheel on a tag, and the README's install line: the next slices of #333.
- `doctor` was not run in a clean container, on macOS, on a machine with another OpenGL device, or with
  bubblewrap installed (the sandbox check is the probe `harness.sandbox.probe` already has; here it
  only ever said "not installed").
- CI's new steps had not run when this was written.
- `doctor` does not read a `.env` file for a vision key, though the older verifier does
  (`agents.keys.load_dotenv`): a key only there is reported absent.
- `sample`'s own check for `patch` is not moved onto the shared list; it still raises its own error.
- The disk figure (1 GB) is room to spare, not a measured need.
