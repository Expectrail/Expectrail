# Keep a published run available on quota refusal and serialize cold asset imports (#494)

## What changed
Run it remembers a result once it has read the published status for that request and sample. A quota refusal can open that result even while the latest-run index is in flight.

The harness turns off parallel asset import for the editor on the disposable project copy. It restores the original project settings before replay, including after an error. On SIGABRT it logs a bounded tail of Godot's stderr and propagates the failure.

## What was run
A Chromium test held the latest-run index until the quota message appeared. It reproduced the original assertion on main and passed with the change. The real Godot editor reported threaded asset import on before and off after. Both imports produced the same digest across 74 imported files and the same slope trace digest.

The original Chromium smoke and both assertions in the Godot slope class passed in all 20 invocations before and all 20 after, alongside full discovery. Each slope invocation started with an empty import cache.

Full discovery ran twice per tree. Before, both runs reported 3,694 tests, OK, 46 skipped. After, both reported 3,695 tests, OK, 46 skipped. Neither tree had a failing or erroring test.

Concurrent cold imports on separate game copies also ran with shared and with separate editor profiles. Six imports per condition per tree exited successfully, with identical imported files and empty stderr.

## Not done
The original CI job did not record Godot's stderr. A cold-import race is reported on the same engine revision in godotengine/godot#125245, in a different project and the Mono build. The exact native cause of the CI abort remains unconfirmed.
